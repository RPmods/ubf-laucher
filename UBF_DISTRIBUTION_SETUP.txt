UBF y UBFLauncher: distribución, instalación y Releases
========================================================

------------------------------------

- Juego UBF: Unreal Engine 5.8.2, versión 1.0.3-beta.
- Launcher: WPF/.NET 8, versión independiente 1.0.10.
- Repositorios separados: RPmods/ubf y RPmods/ubf-laucher.
- Releases, tags, paquetes ZIP y metadata de actualización nunca se comparten entre productos.

1. Contenido y arranque de UBF
-----------------------------

El proyecto ya no contiene mapas de juego propios ni el contenido de plantilla Third Person. El mapa inicial y el del juego usan el mapa vacío incluido con Unreal (`/Engine/Maps/Entry.Entry`); `UBFPresentationGameMode` monta la presentación encima. No reemplazar esa configuración con `Lvl_ThirdPerson`.

Los recursos de presentación son:

- `Content/Presentation/Videos/intro.mp4`
- `Content/Presentation/Videos/videobackground.mp4`
- `Content/Presentation/Audio/musicintro.mp3`
- `Content/Presentation/Audio/musicintrobucle.mp3`
- `Content/Presentation/Images/logo.png`

`musicintro.mp3` se reproduce una vez. Al terminar, el callback de MediaPlayer inicia `musicintrobucle.mp3` en bucle. El video de fondo también se repite. El audio anterior `introdution_ubf.mp3` ya no forma parte del flujo.

En Shipping, `UBFGameInstance` exige la cadena de procesos de UBFLauncher y la variable de sesión `UBF_LAUNCHER_USERNAME`. El launcher inicia directamente `UBF/Binaries/Win64/UBF-Win64-Shipping.exe`, no el bootstrap `UBF.exe`: así permanece asociado al proceso real y la validación reconoce el launcher como padre. La apertura directa de `UBF.exe` o del binario Shipping no deja accesible el menú. El launcher pausa su propia música hasta que UBF se cierra. La interfaz actual de UBF solo presenta la intro y el menú beta; el botón `JUGAR` del juego conserva el mensaje de error beta.

Conservar `UBF.uproject`, `Config/`, `Source/`, `Build/Windows/Application.ico` y los recursos de presentación. Los assets y fuentes retirados siguen en el historial Git. No subir `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/` ni archivos de trabajo del editor. Los videos grandes usan Git LFS.

2. Compilar UBF Shipping
------------------------

Ejemplo PowerShell. Pasa cada argumento por separado para conservar las rutas que contienen espacios:

```powershell
$Project = 'C:\ruta\al\UBF\UBF.uproject'
$Archive = 'D:\Builds\UBF-v1.0.3-beta-Win64-Shipping'
$UAT = 'C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\RunUAT.bat'
& $UAT 'BuildCookRun' "-project=$Project" '-noP4' '-platform=Win64' '-clientconfig=Shipping' '-target=UBF' '-build' '-cook' '-stage' '-pak' '-iostore' '-archive' "-archivedirectory=$Archive" '-prereqs' '-unattended' '-utf8output'
if ($LASTEXITCODE -ne 0) { throw "UAT terminó con código $LASTEXITCODE" }
```

La carpeta que contiene `UBF.exe` (normalmente `Windows/`) es la raíz que recibe el script de empaquetado. Antes de publicar, confirma `BUILD SUCCESSFUL`, UAT con código 0 y los recursos de presentación staged. Prueba el arranque Shipping desde esa carpeta: la ventana del juego debe aparecer al iniciarlo desde UBFLauncher y el proceso debe permanecer activo.

3. Crear el paquete ZIP y manifest del juego
--------------------------------------------

`New-GamePackage.ps1` crea un ZIP sin carpeta envolvente, verifica `UBF.exe` en la raíz y excluye archivos `.pdb` de símbolos de depuración que no necesita el jugador. El build local conserva esos símbolos. El paquete debe quedar fuera de la carpeta build:

```powershell
.\New-GamePackage.ps1 -BuildDirectory 'D:\Builds\UBF-v1.0.3-beta-Win64-Shipping\Windows' -Version '1.0.3-beta' -OutputDirectory 'D:\Builds\ReleaseStaging'
```

Sube las fuentes de UBF a `RPmods/ubf`, crea una Release con tag propio (por ejemplo `v1.0.3-beta`) y adjunta `UBF-v1.0.3-beta.zip`. Después de que el asset esté publicado, genera el manifest:

```powershell
.\New-GameManifest.ps1 -GameDirectory 'D:\Builds\UBF-v1.0.3-beta-Win64-Shipping\Windows' -Version '1.0.3-beta' -PackageFile 'D:\Builds\ReleaseStaging\UBF-v1.0.3-beta.zip' -PackageDownloadUrl 'https://github.com/RPmods/ubf/releases/download/v1.0.3-beta/UBF-v1.0.3-beta.zip'
```

El script lee la lista de archivos del ZIP y genera hashes solo para esos archivos, de modo que build, paquete y `manifest.json` coincidan exactamente. Publica `manifest.json` en la raíz de la rama principal de `RPmods/ubf`. Prueba el manifiesto y la descarga sin credenciales, y luego INSTALL, VERIFY y reparación desde UBFLauncher.

4. Funcionamiento de UBFLauncher
--------------------------------

`launcher.settings.json` define `TargetGameVersion` (`1.0.3-beta` en esta revisión) y habilita verificación SHA-256.

- Al iniciar UBF, el reproductor del launcher pausa aunque el medio todavía esté abriéndose. Al cerrarse el juego, la música se reanuda.
- El control de audio muestra un icono de altavoz, estado silenciado, deslizador y tooltip bilingüe.
- Los botones sociales usan iconos vectoriales consistentes para Discord, YouTube, Twitch, TikTok y Web; Twitch apunta a `twitch.tv/rodrigorpmods`.
- VERIFY solo lee el manifiesto y contrasta hashes; nunca descarga el ZIP. Si todo coincide, guarda la versión y deja el juego listo. Si hay diferencias, presenta `ACTUALIZAR` o `REPARAR`; el paquete se descarga solo cuando se confirma esa acción.
- La raíz de instalación debe contener `UBF.exe`, `Engine/` y `UBF/`. No selecciones la carpeta `Binaries/Win64` del proyecto fuente: el launcher la detecta y evita verificar o descargar sobre ella.
- JUGAR inicia el binario Shipping real `UBF/Binaries/Win64/UBF-Win64-Shipping.exe`. Durante el arranque, el botón dice `INICIANDO...` y JUGAR/VERIFICAR se deshabilitan para evitar clics repetidos. El launcher sigue la ventana del juego hasta que se cierre.
- INSTALL/UPDATE/REPAIR valida y extrae el ZIP en staging, rechaza rutas inseguras y archivos no declarados, conserva saves y revierte el reemplazo ante fallos.

5. Actualizar, compilar y probar UBFLauncher
--------------------------------------------

Cada cambio funcional requiere incrementar la versión del launcher en `UBFLauncher.csproj` y `app.manifest`. Revisa también los fallbacks de versión y `version.json.example`. Cambia `TargetGameVersion` únicamente cuando se publique una nueva versión del juego. Esta revisión publica UBFLauncher 1.0.10 y deja UBF en 1.0.3-beta. El diseño no usa un marco decorativo alrededor de todo el juego ni una tarjeta alrededor del estado; mantiene el título, estado/progreso y acciones en una distribución abierta con jerarquía clara.

```powershell
dotnet build .\UBFLauncher.slnx -c Release
dotnet test .\tests\UBFLauncher.Tests\UBFLauncher.Tests.csproj -c Release
.\publish.ps1
```

`publish.ps1` regenera el launcher y updater self-contained y crea `publish/UBFLauncher-update.zip`. Limpia únicamente las salidas dentro de `publish/`. Antes de subir, comprueba código de salida, versión PE/ProductVersion, ZIP, SHA-256, ejecutables, settings y assets; abre `publish/launcher/UBFLauncher.exe` y confirma que muestra su ventana.

6. Crear una Release del launcher
---------------------------------

Después de probar el build actual:

1. Sube fuentes a `RPmods/ubf-laucher`.
2. Crea el tag independiente `launcher-vX.Y.Z`.
3. Adjunta el ZIP recién compilado `publish/UBFLauncher-update.zip`.
4. Confirma el tamaño y SHA-256 del asset y prueba su URL directa HTTPS sin credenciales.
5. Actualiza `version.json` en la rama principal con la URL y el hash reales:

```json
{
  "version": "1.0.10",
  "downloadUrl": "https://github.com/RPmods/ubf-laucher/releases/download/launcher-v1.0.10/UBFLauncher-update.zip",
  "sha256": "SHA256_REAL_DEL_ZIP",
  "releaseNotes": "Resumen de cambios"
}
```

No publiques `version.json.example` como metadata activa. Verifica que el launcher detecte la actualización.

7. Separación y limpieza de Releases
------------------------------------

Los ZIP de UBF pertenecen únicamente a Releases de `RPmods/ubf`; el ejecutable/actualizador del launcher pertenece únicamente a Releases de `RPmods/ubf-laucher`. Incrementar UBFLauncher no elimina versiones del juego.

Cuando el launcher nuevo esté publicado y verificado, elimina solo Releases/artefactos anteriores del launcher que hayan quedado obsoletos. Conserva tags, commits y fuentes. No borres Releases del juego por actualizar UBFLauncher. `publish.ps1` solo limpia outputs locales.
