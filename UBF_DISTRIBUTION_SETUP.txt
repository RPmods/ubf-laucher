UBF Y UBFLauncher — PROCEDIMIENTO DE BUILD, PRUEBAS Y DISTRIBUCIÓN
=================================================================

1. PRODUCTOS, REPOSITORIOS Y VERSIONES
--------------------------------------

Juego UBF
- Repositorio: https://github.com/RPmods/ubf
- Proyecto: UBF.uproject (Unreal Engine 5.8.2)
- Tag y Release: vM.m.p[-beta]
- Artefacto: UBF-vM.m.p[-beta].zip
- manifest.json en la rama main describe el juego publicado: versión, URL directa del ZIP, tamaño, SHA-256 y verificación por archivo.

UBFLauncher
- Repositorio: https://github.com/RPmods/ubf-laucher
- Aplicación WPF, .NET 8 para Windows x64.
- Tag y Release: launcher-vM.m.p
- Artefacto: UBFLauncher-update.zip
- version.json en la rama main describe la última actualización del launcher: versión, URL directa del ZIP, SHA-256 y notas.

Las secuencias son independientes. Actualizar UBFLauncher no cambia, reemplaza ni retira un juego. Eliminar una Release obsoleta del launcher nunca autoriza eliminar una Release del juego. No eliminar tags, commits ni fuentes necesarios para reconstruir versiones.

Versiones implementadas en esta revisión:
- Juego UBF v1.0.4-beta, Release https://github.com/RPmods/ubf/releases/tag/v1.0.4-beta.
- UBFLauncher v1.0.14, Release https://github.com/RPmods/ubf-laucher/releases/tag/launcher-v1.0.14.

2. PRESENTACIÓN, INTRO Y AUDIO DE UBF
------------------------------------

La pantalla UMG se crea en NativeOnInitialized, antes de que Slate construya el árbol que dibuja el primer frame. Construirla solamente en NativeConstruct deja el widget nuevo fuera del árbol visible y producía una pantalla negra.

Secuencia audiovisual:
1. Mantener el fondo estático y el logo visibles como respaldo.
2. Reproducir musicintro.mp3, importado como SoundWave en /Game/Presentation/Audio/musicintro.
3. Al terminar ese SoundWave, iniciar musicintrobucle.mp3 (SoundWave en /Game/Presentation/Audio/musicintrobucle) en bucle mediante el callback OnAudioFinished.
4. Reproducir intro.mp4 y cambiar al menú cuando concluye el segmento de intro.
5. Abrir el video de fondo solo al entrar al menú; si no se puede abrir o reproducir, conservar el fondo estático.

No cargar MP3 como MediaSource: son SoundWave. Las rutas UAsset anteriores deben cambiarse si los assets se renombran o se mueven.

Config/DefaultGame.ini incluye Presentation/Audio como tipo Primary Asset para cocinar; Config/DefaultEngine.ini limita la velocidad de cuadros a 30 FPS para reducir consumo en pantallas de espera. El cook también deja Presentation como archivos no UFS para conservar los MP4 externos. No borrar mapas u otros assets requeridos por el cook sin volver a empaquetar y verificar el resultado.

3. MODIFICAR Y VALIDAR UBF
--------------------------

1. Cambiar código y assets en el proyecto Unreal. Mantener la lógica de inicio restringida al flujo de intro y menú solicitado.
2. Compilar UBFEditor Win64 Development desde Unreal Editor o UBT. Resolver primero cualquier error de compilación.
3. Abrir el proyecto en PIE y confirmar visualmente que el primer frame no es negro, que aparece la intro, que musicintro empieza primero, que musicintrobucle empieza al terminarlo, que el menú abre y que el fondo de video solo se usa allí. Inspeccionar Saved/Logs/UBF.log ante fallos.
4. Probar también el build empaquetado Shipping, porque PIE no verifica el cook, los archivos no UFS ni la protección de inicio.
5. Para una nueva versión del juego, incrementar únicamente la versión de UBF y compilar, cocinar, stagear y archivar una build nueva con Unreal Engine 5.8.2. Ejemplo de la build v1.0.4-beta:

& 'C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\RunUAT.bat' BuildCookRun `
  '-project=<ruta>\UBF.uproject' '-noP4' '-platform=Win64' `
  '-clientconfig=Shipping' '-target=UBF' '-build' '-cook' '-stage' '-pak' '-iostore' '-archive' `
  '-archivedirectory=<ruta>\Build\UBF-v1.0.4-beta-Win64-Shipping' '-prereqs' '-unattended' '-utf8output'

El proceso debe terminar con BUILD SUCCESSFUL y código de salida 0. Revisar que se haya archivado Windows/UBF.exe y que Presentation/intro.mp4, background.mp4 y SoundWave cocinados estén presentes.

6. Crear el ZIP a partir de la carpeta Windows empaquetada, nunca de una build anterior:

.\New-GamePackage.ps1 `
  -BuildDirectory '<ruta>\Build\UBF-v1.0.4-beta-Win64-Shipping\Windows' `
  -Version '1.0.4-beta' -OutputDirectory '<ruta>\Build\ReleaseStaging'

El ZIP debe ser nuevo, incluir UBF.exe en su raíz y excluir PDB/debug temporales. Registrar tamaño y SHA-256.

7. Confirmar que las pruebas de Shipping y de inicio mediante UBFLauncher funcionan. Crear el tag v<versión> sobre el commit del código validado; crear una Release prerelease en RPmods/ubf y adjuntar únicamente el ZIP recién construido. Publicar la Release después de verificar el asset y su tamaño.
8. Después de publicar el ZIP, generar manifest.json con el script incluido. Ejemplo:

.\New-GameManifest.ps1 `
  -GameDirectory '<ruta>\Build\UBF-v1.0.4-beta-Win64-Shipping\Windows' `
  -Version '1.0.4-beta' `
  -PackageFile '<ruta>\Build\ReleaseStaging\UBF-v1.0.4-beta.zip' `
  -PackageDownloadUrl 'https://github.com/RPmods/ubf/releases/download/v1.0.4-beta/UBF-v1.0.4-beta.zip'

El script comprueba que el manifest y el ZIP coincidan con la build; publicar el manifest en main de RPmods/ubf después de crear la Release. El modo VERIFICAR del launcher compara hashes locales sin descargar el ZIP. Solo instalar/actualizar/reparar descarga el paquete.

4. ACTUALIZAR, PROBAR Y PUBLICAR UBFLauncher
--------------------------------------------

1. Modificar el proyecto fuente en D:\proyectos\UBFLauncher y mantener el repositorio fuente en RPmods/ubf-laucher actualizado.
2. Incrementar la versión propia del launcher en UBFLauncher.csproj, app.manifest, badge/fallbacks de versión y version.json.example. Mantener version.json sincronizado después de publicar el asset.
3. Cambiar Settings.TargetGameVersion en launcher.settings.json y Models/LauncherConfig.cs solamente cuando haya una versión nueva del juego publicada y su manifest corresponda. No igualar ambas versiones por obligación.
4. Compilar y correr la suite existente:

   dotnet build .\UBFLauncher.slnx -c Release
   dotnet test .\tests\UBFLauncher.Tests\UBFLauncher.Tests.csproj -c Release

5. Hacer una prueba básica visible de UBFLauncher. Comprobar que carga la ventana, medios y configuración; VERIFICAR no debe bajar ZIP cuando hashes y versión local ya coinciden; INSTALAR/ACTUALIZAR debe mostrar progreso; JUGAR debe pasar a INICIANDO..., rechazar clics repetidos y abrir el ejecutable Shipping del juego; la música del launcher debe pausarse mientras el juego esté abierto.
6. Ejecutar .\publish.ps1. El script compila self-contained launcher y updater, verifica los .exe y medios, retira archivos .pdb de depuración del artefacto y produce publish/UBFLauncher-update.zip. Limpia únicamente las carpetas de build/archive dentro de publish/; no borra el código, tags, historial, ni Releases remotas. No reutilizar ningún ZIP anterior.
7. Inspeccionar ProductVersion del ejecutable, tamaño y SHA-256 del ZIP actual. Confirmar que el ZIP se generó después de los cambios funcionales y que sus recursos están presentes.
8. Confirmar la prueba básica antes de crear la Release. Crear tag launcher-v<versión> sobre el commit probado, crear Release en RPmods/ubf-laucher y adjuntar el ZIP recién construido. La publicación se hace solo cuando el asset correcto esté cargado.
9. Tras publicar, actualizar version.json en main con la versión del launcher, URL directa del asset y SHA-256 medido. Es una metadata distinta del manifest del juego. Verificar la descarga pública, tamaño y hash del asset.
10. Solo cuando la nueva Release esté publicada y verificada, retirar la Release/artefacto de launcher anterior que ya quedó obsoleto. Eliminar la Release no es eliminar el tag ni el commit; conservar tags y fuentes reproducibles. Nunca borrar Releases, ZIPs ni historial de UBF por esta limpieza.
